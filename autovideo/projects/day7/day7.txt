如何让大模型 100% 规范输出？
在开发 AI 应用时，我们常需大模型输出 JSON 等标准格式供程序调用。然而，大模型本质是“自由诗人”，要实现从“自由发挥”到“严格填表”的转变，需经历三层逻辑关卡。
1. 引导层：Prompt Engineering（软约束）
这是最基础的“口头约定”。
操作方法： 通过 Few-shot（少样本提示） 给出标准范例，或明确 定义 Schema 告知字段要求。
局限性： 就像老师考前划重点，学生（AI）虽然懂了规则，但容易写着写着“飘了”。比如在 JSON 前多加一句“好的”，或混入非法符号，导致程序解析失败。
2. 协议层：JSON Mode / Tool Use（硬约束）
这是厂商提供的“物理干预”方案，强制锁死输出形态。
实现原理：
Logit Bias（概率干预）： 强制将非法字符的出现概率降为 0，逼迫模型只能在合法字符中选择。
FSM（有限状态机）： 充当实时的“语法交警”。例如输出完 "Key": 后，算法强制限制下一个字符只能是 {、[ 或 "，绝无他选。
通俗类比： 给 AI 的键盘装了“物理锁”，想输出废话时按键直接卡死，只能敲出合法的 JSON 字符。
3. 工程层：Pydantic + Instructor（质检与纠错）
格式正确不代表内容正确（如 age 字段填了“二十五岁”而非数字），需进行最后的数据安检。
Pydantic（安检门）： 定义严格的数据类型，拦截类型不匹配的内容。
Instructor（纠错闭环）： 建立“输出-校验-反馈”的自动化闭环。一旦报错，系统自动将错误信息回传 AI，要求其“哪里错了改哪里”，直到通过校验。
总结： 这套流程从“口头叮嘱”进化到“监考老师盯着”，最后“机器阅卷复核”，确保输出万无一失。
